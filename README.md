# Suzu Memory

面向持续陪伴型 Agent 的本地优先长期记忆引擎。

Suzu Memory 将对话和活动保存为可追溯的本地事件，再逐步形成带有主体、时间、证据与关系的长期记忆网络。它让 Agent 在回复前只取回眼前问题真正需要的少量上下文，而不是反复塞入整段聊天记录或不断膨胀的摘要。

Apache-2.0 · Node.js · SQLite · 可配置模型与 Embedding Provider

## 为什么是陪伴型记忆

长期相处的记忆不只是文档分块检索。

- 一次经历、稳定偏好与暂时状态需要被分别看待；
- 用户、Agent、第三方和双方共同关系不能混成同一个主体；
- 新的认识可以补充或修正旧认识，但原始事实与来源证据仍应保留；
- 想起一件具体事情时，应能回到相应的证据，而不是只得到笼统概括。

## 它认识人的十二个维度

事件层记录“发生过什么”；持续认识层记录“一个主体在一段时间内是怎样的、相信什么、在意什么、与谁处于怎样的关系”。

| 身份与生平 | 观念 | 偏好 | 习惯 |
| --- | --- | --- | --- |
| 气质与应对倾向 | 价值与优先级 | 目标与未完事项 | 能力与熟练度 |
| 关系认识 | 情绪联结 | 自我认识 | 现实条件 |

这些维度不会把一次表达草率定为永久结论：每条持续认识都可以保留主体、适用范围、时间变化和来源证据。

## 核心能力

| 能力 | 作用 |
| --- | --- |
| 证据优先 | 对话以追加式事件保存；长期记忆可回到原始消息与来源。 |
| 时间与边界 | 区分发生、获知与记录时间，并隔离不同主体、关系与现实框架。 |
| 状态演化 | 偏好、观念、习惯、目标、能力和关系可以被补充、纠正或取代，同时保留历史。 |
| 关系化记忆 | 主题、事件、人物与关系能够交叉关联，而不是被塞进单一摘要。 |
| 有边界的召回 | 结合当前问题、主体、时间和证据，提供少量可用上下文。 |
| 可审核维护 | 对可疑结论保留证据与操作记录，支持人工核对、驳回和撤销。 |
| 事件来源管理 | 按 Agent 实际接纳的经历增量消费，检索校验来源范围，清理可恢复并覆盖受管备份。 |
| 独立召回控制 | 详细检索轨迹与召回激活分别控制，支持稳定使用身份去重和多条候选的可读预览。 |

## 引擎接口

`@suzu-memory/service` 提供事件追加、后台维护、检索、召回激活、审核、备份与恢复接口。具有正式事件存储的宿主可使用 [Event 来源契约](docs/event-source-contracts.md)声明已提交事件与 Agent 已接纳经历的有效范围；该文档同时说明候选预览、轨迹与激活选项。模型与 Embedding Provider 通过配置或函数注入。

## 数据、Provider 与隐私

- 长期记忆库、原始证据、审计轨迹和备份默认保存在本地数据目录；
- 模型与 Embedding Provider 由本地配置决定，只有启用相应能力时才会发送所需文本；
- API Key、真实聊天、数据库、缓存、备份和运行产物均不应提交到仓库。
