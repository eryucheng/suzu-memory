# 检索执行与索引

检索保留同一套候选门控、评分、主体与来源约束。SQL 预筛只建立候选 ID 的完整超集，不按初步排名截断；词法、BM25、实体、向量的候选共同进入现有评分与关联展开。

## 执行选项

通过服务的 `defaults.retrieval` 或单次 `search` 的 `options` 配置：

| 选项 | 默认行为 |
| --- | --- |
| `execution` | 自动选择；`inline` 强制调用线程，`worker` 强制检索线程 |
| `workerThreshold` | 同一 Agent 的有效检索记录达到 1000 条时使用线程 |
| `sqlPrefilter` | 开启；`false` 使用原全量评分路径 |
| `sqlPrefilterThreshold` | 有效节点达到 1000 条时启用 SQL 预筛 |
| `embeddingCache` | 开启；`false` 每次重新加载向量索引 |
| `embeddingCacheMaxBytes` | 每个执行线程估算缓存预算 256 MiB；可设置 0 至 1 GiB 的整数 |
| `workerIdleTimeoutMs` | 空闲线程保留 5 分钟；可设置 0 至 1800000 毫秒 |
| `deferNodeBodies` | 大库开启延迟正文读取；`false` 使用完整节点读取，便于对照验证 |

小库继续在调用线程执行全量路径。线程按数据库复用，最多同时保留两条；Embedding 提供者仍在调用方环境执行。任务 ID 区分并发调用，取消信号传递到检索任务；没有空闲容量时等待或响应取消。空闲线程默认 5 分钟后退出，等待中的其他数据库可以提前回收空闲线程，调用 `MemoryService.close()` 可主动释放当前库的空闲线程。空闲线程不阻止宿主进程正常退出。

线程与调用线程共用原检索实现。来源范围随任务传递，候选、向量与证据继续使用同一 SQLite 读快照；来源清理后的迟到结果仍须通过原有校验。

## 索引维护

Schema 45 增加 `memory_fts_rows`，按记忆 ID 查到全文索引的 rowid，更新时据此删除旧索引。迁移回填已有索引；新库在正常写入时同步维护。词法归一化文本属于这个索引，直接 SQL 修改正文时会使该字段失效，预筛因此保留该节点，避免漏掉候选。没有映射表的旧只读库保留全量路径。

问句在节点评分循环外准备，节点复用同一组词项。SQL 预筛包含所有可能词法匹配以及其他检索路线的候选，未建索引和待确认候选也保留。

大库先读取节点的资格、时间、主体和状态字段，暂不读取标题与正文。普通路线预筛后通过主键批量读取候选完整节点；关联完成需要其他节点字段时按需读取。节点读取器在一次检索内复用已读内容；延迟读取与节点资格使用同一 SQLite 读事务。日期浏览在格式化实际返回内容或执行所需的关联完成时读取完整节点。小库及禁用预筛时保留完整节点读取路径。

向量缓存按数据库身份、Agent、模型、读取状态及数据库修订号区分。节点或向量写入触发修订号变化；缓存更新后再执行当前来源与可见性过滤。返回向量为独立副本，调用方修改不会污染缓存。每个执行线程的缓存按访问顺序回收，最多 16 项，默认估算容量预算为 256 MiB；降低预算时立即回收已有缓存。五万条 1024 维 Float32 向量约占 195.31 MiB，按每行额外估算 512 字节后约为 219.73 MiB，可放入默认预算。超预算的完整索引仍直接读取，不缓存；返回副本、检索节点和 SQLite 的内存另计。线程退出会释放该线程的缓存；数据写入后会按修订号重新加载。
