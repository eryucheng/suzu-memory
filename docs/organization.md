# 记忆整理与模型接入

默认 OpenAI-compatible generator 声明 `supportsPlannedOrganization: true`。累计记忆达到维护阈值后，`runSemanticTaskMaintenance` 将批次原子交给持久化 consolidation run；`runSemanticMemoryMaintenance` 在同一轮继续执行该计划。单独调用前者只完成计划交接。

同一个计划负责新增记忆之间、新增与历史记忆之间的分组及因果判断。程序先发现已有容器和相关成员，模型判断成员归属；请求过大时按完整记忆分段，后续分段可引用前面已经计划的分组。成员汇总完成后，每个受影响容器生成一次完整概述。多个容器的概述可共享一个请求中的成员材料。

因果分析是附加任务，识别关键经历、动机和条件对人物后续选择、目标、关系及持续反应的影响，返回发现的关系或空列表。它沿用本轮材料及合批入口。每个模型任务只接收本职语义判断所需的说明；字段和可选引用由 Schema 描述，去重、来源版本、保存与恢复由程序处理。

关系区分 `causes`（发生原因）、`reason_for`（决策理由）和 `condition_for`（适用条件），方向从原因、理由或条件指向受影响的记忆。`rationale` 是保留解释归属和确定程度的简短解释，`scope` 保存原话明确的适用范围。范围随提案的 `metadata.scope` 及拥有的边保存。召回为选中的记忆读取符合当前来源范围和关系强度阈值的解释，将说明和范围附在正文中；背景记忆不必占用另一条正文名额，其来源一并计入追溯。范围变化本身不执行目标或其他状态转换。

## 审核是事后管理

通过程序校验的整理结果自动生效，供召回和后续维护使用。审核台提供事后查看、确认、纠错和撤回；不打开审核台、不点击接受，不能阻断正常运行。`pending` 表示尚未人工复核，不表示结果不可使用；自动生效也不应把记录改成人工已接受。

人工确认只记录复核结论，不重复生成或应用结果。驳回、撤回须移除该提案仍然拥有的结果，保护后续修改和其他有效结果，并保留可追溯记录。重试、重启和重复生成不得复活已撤回结果。

格式、引用、主体与世界范围、原始证据和来源版本仍由程序校验。未满足这些条件属于数据或分析尚未完成，须保留明确的失败与自动恢复路径；不能仅因尚未人工复核而停用有效结果。生成、保存、召回和历史数据恢复遵守同一合同。

符合直接自述规则的非偏好状态在完成分析的同一事务写入正式结果及其归属，审核继续显示待复核。确认沿用已写入的结果，撤回按记录清除该次状态版本或补证及其证据清单。原话编辑或软删除后，相应证据退出使用。失去全部依据的状态暂时退出召回，恢复同版原话可恢复仍归原提案所有的结果。可写服务启动时，旧版系统代确认的记录恢复为待复核，并保留原自动操作的审计信息。历史分析已完成但尚未应用的结果仍按当前程序校验恢复。

已应用的状态变更同时记录新版本及其对旧版本的截止。人工撤回或原始依据失效时，撤回仍归该变更所有的截止，沿已记录的版本恢复最近仍有效的旧状态。恢复原话时核对旧状态的版本和当前归属。只有已生效待审记录的旧库也按来源恢复。人工撤回及后续修改保留其优先级，审核台和实际写入沿用同一撤回条件。

本人明确表达的偏好在同一事务保存分析结果和实际写入。新建、补证、替换和场合例外均可在待复核时供正常召回使用。确认只记录审核。撤回按这次写入的归属处理偏好版本、历史截止时间和补充证据。软删除原话会让受影响的结论停止生效，观察保留供复查和恢复。恢复同版原话后，由原始观察和来源快照校验恢复原结论。软删除补证原话时，仅暂停使用该补证，其余有效证据继续支持原结论。恢复同版原话即可继续使用补证，人工撤回会解除补证关系。新版结论、人工撤回和已改写的来源优先。明确改口沿用同一事项的匹配结果及范围判断。评估工具可另行比较行为反证、局部拒绝和暂时条件。

从行为形成的推断偏好复用已完成的分析，按当前有效证据形成带版本的状态。状态在待复核时自动生效，确认只记录审核，撤回按所属版本回退。编辑、删除、恢复原话或清除来源后，复用当前有效证据重新累计，证据中的会话标识用于区分场景。历史版本升级保留审核记录，失去证据依据的结果退役，有效版本按写入归属恢复。跨层晋升核对当前生效的推断版本、规范审核快照及专用政策。

有明确对象和范围的第三方转述，以及已发生的单次选择、接受或回避，保存为可检索的证据记忆。记录保留说话人、原话和证据版本，可通过记忆管理单条撤回。证据记忆独立于主体的当前偏好，来源失效时相应记录退役。启动时可复用历史分析恢复仍有效的记录。

因果关系的 `proposeMemoryRelation` 在同一事务内保存提案和有效边，返回的 `pending` 记录带有 `result_edge_id`。`resolveMemoryRelationProposal` 的 `accept` 记录确认，`dismiss` 撤回仍由该提案拥有的边；`revokeMemoryRelationProposal` 可撤回尚未复核或已经确认的有效结果。后续改写拥有独立版本，旧提案不能撤销它。

可写的 `MemoryService.initialize()` 自动恢复尚未应用的历史因果提案。仅使用 core 的接入方在升级或启动恢复阶段调用 `materializePendingMemoryRelationProposals`；该函数按页处理全部待恢复记录。保存的来源版本有效时直接补建边；旧版缺少版本但保留了原始证据检查点时，核对证据和未改动的端点后恢复。无法确认当前有效性的材料交给现有维护队列重新分析，失效端点对应的旧结果退役。恢复保留人工审核状态，不自动标为已接受；只读服务不执行恢复写入。

待审或已确认的结构提案均可撤回。撤回按版本归属移除提案写入的内容，保留原确认记录、人工改写的主题和后来独立加入的成员。同一证据版本下重复提交已撤回的分组会沿用撤回决定。旧版已经生效的结构可根据现有结果和已链接成员完成确认。首次应用结构仍需原输入版本。

成员原文变更后，沿用已确认的分组并按当前成员刷新摘要。移除摘要引用的成员也会触发刷新。撤回追加时，只有成员证据版本仍对应原快照，旧摘要才可回放。召回跳过已失效的摘要及依赖它的旧摘要，仍可检索有效成员。刷新失败任务关闭后继续等待有效版本。启动恢复从尚未应用的结构提案分页处理。

## Generator 合同

自定义 generator 选择支持新流程时，设置 `supportsPlannedOrganization: true` 并实现以下任务。未声明时保留原结构提案流程；已经开始执行的旧批次继续使用原合同。

| schemaName | 程序侧输出 |
| --- | --- |
| `memory-structure-memberships-v1` | `{ proposals: [...] }`；create 包含 kind、title、memberIds、主体和角色、confidence、rationale；attach 包含 targetMemoryId、memberIds、confidence、rationale。两者均不输出 content。 |
| `memory-organization-decisions-v2` | `{ structure, relations }`；structure 使用成员合同，relations 使用 v2 关系合同。仅当同一 generator 同时声明 `supportsCombinedConsolidation` 时合并调用。 |
| `memory-relation-proposals-v2` | `{ proposals: [...] }`；每项包含 relation、fromMemoryId、toMemoryId、evidenceSourceIds、confidence、rationale，及已知的 scope。 |
| `memory-consolidation-combined-v2` | `{ structure, relations }`；structure 使用原结构提案合同，relations 使用 v2 关系合同。 |
| `memory-structure-summary-v1` | 已有 `{ title, content }` 合同。 |
| `memory-structure-summary-batch-v1` | 按请求声明的 `group1`、`group2` 等键分别返回 `{ title, content }`；每组只概括自己的 memberIds。 |

`request.schema` 是精确的程序侧合同，应以实际请求为准。发给模型时使用 `modelInput ?? input`、`modelSchema ?? schema` 和 `systemPrompt`，返回值通过 `decodeOutput` 还原后交给领域处理。成员判断在模型侧使用 `creations`、`attachments` 及受限的短 ID 选择；宿主不应把这个格式当作程序侧的 proposals 保存。

关系模型侧使用 `anchorMemoryId`、`relatedMemoryId` 和 `anchor_to_related` / `related_to_anchor`，由解码器还原方向。v1 关系及合批合同仍可由任务校验入口读取；已有提案、证据、人工撤回及恢复检查点在升级时保留。

程序使用与正式提案相同的 `validateStructureMembership` 校验主体、世界和成员范围，在生成概述前排除非法成员计划。日期边界、来源版本、合并成员、费用归属和恢复状态由程序维护；具体事项是否相同、是否应该归组以及因果关系仍由模型判断。

## 恢复和费用

成员判断、完成的关系判断、概述和已落库提案都保存在原 consolidation run 的检查点中，沿用同一租约。有效子结果保留；重试补齐缺失部分。概述部分成功时，可以先提交成功的容器；重新打开数据库后复用其余已完成判断。容器或成员来源变化时重新规划，旧执行者失去租约后不能提交。

完整材料超出预算时拆分任务；单个不可再分的完整任务仍超限时保留检查点进入审核，不截断原文或概述成员。模型调用失败或返回后材料失效，其已发生用量仍记账。共享回执只记一次；成员阶段的费用 feature 为 `memory-organization-membership`，最终概述为 `memory-structure-summary`，回执 metadata 保留实际 schemaName。

`assertMemoryTaskRequest`、`validateMemoryTaskOutput` 注册上述合同。后者用于严格检查一个完整输出；运行时由各领域 owner 接收和诊断子结果，避免把有效子结果随失败部分一起退回。
