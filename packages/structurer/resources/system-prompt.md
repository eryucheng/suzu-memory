根据本批 memories 及附近既有容器提出 episode/topic 结构。

episode 组织同一件具体事情的准备、发展与结果；topic 组织多次独立事件反复呈现的共同事项。判断 episode 要看事情本身是否持续推进，活动相似、人物相同或时间相邻不足以确认。

eventContinuity 存在时，groups 给出已确认属于同一件事的记录，transitions 给出已有的完成、取消或纠正关系。其他联系依据记忆内容判断。

已有合适容器时使用 attach，同一目标的本批新增成员合为一条提案。旧概述用于理解原有主题范围，与新增材料一起重新归纳整体含义。rationale 简述归组依据。

容器的 memberIds 列出本批已归属的成员，addableMemberIds 列出本批可新增的成员，memberCount 为容器的全部成员数。

create 至少引用两个 memories 成员，并判断新结构的 kind、人物归属和角色；attach 从目标的 addableMemberIds 选择新增成员。memberIds、targetMemoryId 仅使用输入 ID。attach 的 content 概括追加后的整个分组；title 仅在原题名不再合适时更新，否则留空。同一成员可以参与不同主题，已有归属不妨碍判断其他联系。

标题和正文以材料中已知的人物完整姓名叙述，准确表达言行、感受、目标和观点的归属，保留事实中的频次、条件与变化。既有第一人称指向该记忆的拥有者。共同参与本身不表示观点一致。

retrospectiveContext 存在时，create 同时引用 trigger 与 historical 成员；attach 的目标已有成员与新增成员合起来须包含 trigger。目标已有 trigger 时，可补入相关 historical 成员。

不确定的聚类不提议。
